Q5. You run echo $PATH | tr ':' '\n' and see /usr/local/bin appears twice. Is this harmful? What actually happens when bash resolves a command, and why does the order of entries in PATH matter more than duplicates?

Normally its not harmfull.
The shell goes through a strict multi step command resolution pipeline to figure out exactly what code it needs to execute.

1.Tokenization and parsing
before looking up the command bash breaks your input line into tokens.It handles qoutes, expand variables and sets up any input output redirections.

2.Alias expansion
If your input is a single word without an explicit path, bash checks its internal memory of aliases.If it finds a match it replaces your input text with the alias definition and start resolution loop again.

3.Keywords
Bash checks if the word is a structural shell keyword.These are built in syntax elements used for programming logic, such as if,then,for,while...

4.Shell functions
Next bash looks at the functions loaded in its current memory env.If you have a custom function as deploy, it will run that code block

5.Shell built ins
If no function exist bash checks its list of built in commands.These are commands compiled directly into the bash binary itself such as cd,pwd.

6.External utilities($PATH lookup & hashing)
If the input isnt none of above bash assumes it must be a standalone file program sitting somewhere on the hard drive.Bash then first check its hash table.To avoid scanning everytime you type a command bash keeps an internal cache of where it previously found programs.If the program isnt there bash checks $PATH variable from left to right, opening each folder to see if that program exist on them.If it finds the program bash execute it it using execve system call.If nothing was found it stops and print command not found.

order matter because bash stops on the moment it find a match.if you have two versions of the same program in different paths bash only execute the version that it finds first.Th
e other version is completely ignored.
