Unix is designed that way because there is only one way a command can succeed but there are so many ways to fail them.If a command fails user or OS need to know why it failed.If 1 means true/success you would only have 0 left to know why it failed. By making 0 means successs unix frees up the numbers from 1 to 255 to act as unique error codes.

Q8. Look at this practical pattern:

bash


check_service() {
    SERVICE=$1
    if systemctl is-active --quiet "$SERVICE" 2>/dev/null; then
        echo "✅ $SERVICE is running"
    else
        echo "❌ $SERVICE is NOT running"
    fi
}
check_service ssh
check_service nginx
check_service fake_service
Why does the function use 2>/dev/null after the systemctl command? What would happen without it? And why does --quiet matter here?

2 stand for standard error(stderr) in bash. /dev/null is like a balck hole in linux. It deletes anything thrown in to it completely.so in this function this is used to redirect all the stderr output to the /dev/null.In this function there is no need of 2>/dev/null because --quiet flag is already suppressing the stdout and stderr. But if you only used 2>/dev/null systemctl command will print its stdout to the terminal (active,inactive or unknown). --quiet flag matters here because you redirected stderr only. It will still print the stdout of the systemctl making the output of the script messy.If you redirected both stdout and stderr both using >/dev/null you dont need --quiet flag here.
