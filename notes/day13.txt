-e flag stand for error. It exit the execution of script if any command inside the script exit with a fail exit code. first command will create a directory inside /tmp. cp command copy nonexist.txt to that folder and then echo will print Done.Assuming that file does not exist, cp will exit with a non zero exit code and bash will stop executing the script. Q2. What's the difference between set -e and checking $? manually after each command? When might you prefer one approach over the other?

set -e automates error handling by emmediately exiting the script on failure,while $? manually give you precise control over how to handle specific errors without breaking the execution.When you want to run the next task (command,function,loop...) based on the exit code of previous command $? is the ideal choice.set -e is highly effective in linear,predictable scripts where any single faliure means the entire process should halt immediately.Its ideal for CI/CD.

Q4. A script has this line: grep "error" /var/log/syslog | wc -l. If grep finds no matches, it exits with code 1. With set -e alone, the script continues. But if you add set -o pipefail, what changes and why?

with -e alone bash only checks the exit code of the last command in pipe.So even though grep failed script will continue its execution.But when pipefail is added bash will check all the exit codes in the pipeline and if one of them failed bash will terminate further execution.

Q6. You see this pattern in a script:

in bash $$ is a special shell variable which reprecent the PID of the currennt running script or shell. Its not hardcoded to avoid data collision. If two or more users or instances ran the script at the same time with harcoded file path they will overwrite eachothers temporary data.In this way they have differnt file names with their PIDs.(two processes cant have the same PID).But $$ is no longer recommended for /tmp because predictability of PIDs.PIDs are assigned sequentially by the OS.An attecker can guess what the next PID be and do a symlink attack.

Q7. Compare these two error-handling patterns — what's the practical difference?

bash


# Pattern A
mkdir /some/path 2>/dev/null
if [ $? -ne 0 ]; then
    echo "Failed"; exit 1
fi
# Pattern B
mkdir /some/path || { echo "Failed"; exit 1; }

There are multiple differences between code brevity,readability,error suppression and compatibility with set -e.pattern A has more commands to achive the same goal that achieved by pattern B.Error messages are deleted the moment they were written in pattern A but pattern B error messages are visible and easy to debug.In pattern A set -e will terminate its execution the moment mkdir failed but pattern 2 will actually run faild echo statement before termination if mkdir fails.
